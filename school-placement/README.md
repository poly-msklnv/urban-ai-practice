# Практика 3: размещение школ в Eixample

Локальное приложение для ручного сравнения школ в нескольких кварталах и полного перебора
размещения **одной** школы. Работает на сохранённых данных практики 2 без API-ключей,
скачивания города, CDN и обращения к языковой модели.

## Запуск

Из корня репозитория, Python 3.11 или 3.12:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r school-placement/requirements.txt
python school-placement/app.py
```

В Windows вместо `source` выполните `.venv\Scripts\Activate.ps1`.
Откройте **http://127.0.0.1:8765**. Остановка: Ctrl+C. Порт можно изменить: `--port 8766`.
Приложение слушает только loopback; это локальный учебный инструмент, без многопользовательского сервиса.

## Как пользоваться

1. Выберите квартал на карте или в списке. Задайте положительную целую вместимость и нажмите
   «Добавить школу». Повторите для нескольких школ, затем «Рассчитать сценарий».
2. Переключайте карту: исходное состояние / сценарий / изменение обеспеченности в процентных пунктах.
   Таблица и карточка показывают исходные и сценарные значения. Если изменён черновик,
   подпись предупреждает, что карта ещё показывает последний расчёт.
3. Задайте вместимость автоматического размещения и нажмите «Разместить автоматически».
   Индикатор показывает число проверенных кварталов. Все варианты ранжируются по сокращению
   суммарного дефицита. Показываются **все** равноценные лучшие ID; на карте открывается первый по ID.
   Нажмите «Показать» у любой строки, чтобы пересчитать и открыть её сценарий.
4. Назовите и сохраните нужные рассчитанные сценарии, чтобы сравнить их с исходным и друг с другом.
   Они хранятся в памяти страницы до перезагрузки. Для сохранения на диск выгрузите CSV
   по кварталам и отдельно CSV перебора. «Сбросить изменения» возвращает исходное состояние,
   очищает размещения и рейтинг, но сохраняет именованные сценарии для сравнения.

Нет спроса: обеспеченность не определена, показано «—», квартал серый. Это не 0%.
Одинаковые результаты поиска сравниваются по целому числу мест, поэтому допуск округления не нужен.
Ошибка отдельного варианта показывается в рейтинге; неполный перебор не объявляется оптимальным среди всех кварталов.

## Данные и воспроизведение исходного расчёта

- `../data/blocks_metrics.geojson`: единственный исходный набор кварталов, населения, вместимости
  и сохранённых показателей практики 2. Читается без изменений.
- `input/accessibility_matrix.csv.gz`: матрица 1039 × 1039, строки — кварталы спроса,
  столбцы — кварталы школ, время в минутах. Gzip читается напрямую pandas.
- `input/accessibility_matrix.audit.json`: параметры, версии, контрольные суммы, результат сверки.
- `results/`: отдельные результаты эксперимента, не входы модели.

**ID — позиция объекта в итоговом GeoJSON, с нуля**, как индекс после чтения в ноутбуке.
В исходном GeoJSON не записан постоянный кадастровый ID: порядок объектов менять нельзя.
Промежуточные `blocks_landuse`, `blocks_buildings`, `schools_blocks` содержат 1056 объектов,
а итоговые `blocks` и `blocks_metrics` — 1039. Они относятся к разным состояниям расчёта;
нельзя присоединять промежуточные таблицы по совпавшему номеру строки. Используются согласованные
геометрия и все показатели из итогового файла. Строки и столбцы матрицы проверяются и выравниваются по ID.

Оригинальные `accessibility_matrix.pkl` / `walk_graph.pkl` исключены из Git и в доступных локальных
файлах отсутствовали. Матрица восстановлена по процедуре исходного ноутбука
(`iduedu==0.4.1`, скорость `83.3333` м/мин, `calculate_accessibility_matrix`) на
**историческом снимке OSM 20.10.2026 21:00 UTC**. При старте приложение заново считает исходное
состояние и сравнивает **все 10 сохранённых школьных показателей каждого из 1039 кварталов**
с допуском `1e-8`. Совпадение достигнуто. При несовпадении или отсутствии матрицы доступны
только сохранённые исходные показатели, расчёты заблокированы с объяснением.
Это подтверждает воспроизведение сохранённого расчёта школ, а не побитовое равенство утраченному PKL.

### Почему первоначально разошлись 17 мест

Актуальный граф OSM от 13.11.2026 содержит 21256 направленных рёбер вместо 21724
в историческом графе. Времена доступа изменились и метод по-другому распределил места:
квартал 126 получил на 17 меньше, квартал 153 — на 17 больше, общий дефицит остался 23353.
Перекодирование `float16`/`float64` разницу не устранило. При неизменном ПО и входах замена
актуального графа историческим полностью восстановила исходные показатели. Исправление:
зафиксирован исторический снимок, сохранена матрица, добавлена строгая сверка при запуске.
[Числа диагностики](results/matrix_drift_diagnosis.json).

Восстановить матрицу заново (интернет нужен **только для этой команды**):

```bash
python school-placement/prepare.py --osm-date 2026-10-20T21:00:00Z --output /tmp/restored.csv.gz
```

Для восстановления из собственного доверенного кэша:

```bash
python school-placement/prepare.py --import-matrix /path/to/accessibility_matrix.pkl --output /tmp/restored.csv.gz
```

PKL может исполнять код при чтении: используйте только собственный доверенный файл.
Если сверка не пройдена, команда завершается с кодом 2; не подменяйте исходные результаты,
чтобы скрыть различие. Аудит сохраняется рядом с матрицей. `--output` обязателен; существующие матрицы
не перезаписываются. После успешного аудита новый файл можно отдельно использовать вместо
`input/accessibility_matrix.csv.gz`, сохранив соответствующий аудит.

## Метод и единицы

`blocksnet==1.0.0a9`, `competitive_provision(population, capacity, matrix, 15, 120,
self_supply=True, max_depth=1)`. Спрос по кварталу — `ceil(population × 120 / 1000)` мест.
Сначала обеспечивается собственный квартал, затем решается исходная задача конкурентного
распределения с вместимостью и доступностью. Это не простое вычитание мест из потребности.

Новая школа увеличивает только `capacity` выбранного квартала; население, время и параметры
фиксированы. Все варианты стартуют с независимой копии исходной вместимости. Целевая величина:
`sum(baseline.demand_left) - sum(scenario.demand_left)`, мест. Изменение мощностей может
перераспределить места между соседями; карта изменений допускает и локальное снижение.

Население — модельная оценка, вместимость существующих школ — 250 мест на школу (63 объекта).
Источники: OSM/Geofabrik Cataluna 19.10.2026, ноутбук практики 2; матрица восстановлена отдельно,
как указано выше. Данные © OpenStreetMap contributors, ODbL; исходные GeoJSON сохраняют свою атрибуцию.
Школы за пределами района, возрастная структура и транспорт не учтены. Выбор квартала не заменяет
выбор участка и градостроительное обоснование строительства.

## Эксперимент и проверки

Выбор А и Б с объяснениями зафиксирован **до** автоматического поиска:
[experiment-selection.json](experiment-selection.json). Воспроизведение:

```bash
python school-placement/experiment.py
```

Скрипт проверяет исходный расчёт, выполняет А (600), Б (300+300), полный В (600),
сверяет автоматический результат с ручным размещением и контрольные суммы входов.
[Отчёт с ответами](results/REPORT.md), [все варианты](results/automatic_600.csv),
[сводка и списки кварталов](results/experiment.json).

```bash
python -m pip install pytest
python -m pytest tests/test_school_placement.py -q
```

Тесты используют настоящий метод BlocksNet на небольших контрольных примерах, проверяют
влияние на соседей, недоступные кварталы, несколько школ, независимость сценариев,
равные лучшие результаты, ошибки/полноту перебора, неправильные ID, вместимости и матрицы,
сброс расчёта и согласованность JSON/таблиц/сумм через локальный HTTP.
Для всех тестов репозитория сначала установите исходный пакет: `pip install --no-deps -e .`,
затем `python -m pytest tests -q`.

Визуальная проверка desktop/mobile и клики по браузерному интерфейсу не выполнены:
доступ CUA к браузеру отключён в настройках сессии. Проверены синтаксис JS,
статическая семантика интерфейса, Impeccable detector и HTTP/расчётный контур;
это не заменяет визуальную приёмку.
